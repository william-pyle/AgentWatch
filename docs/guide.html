Getting started

  1. Download the Windows x64 installer from GitHub Releases and install it for your Windows account.
  2. Open Agent Watch from the Start menu. The Robot Datacenter is included and works offline.
  3. Choose the folder your agents work in. Recent Codex and Claude sessions from that folder and its descendants appear automatically.
  4. Open Settings to enable either provider, reduce motion, or check for updates.

Scroll over the scene to zoom, drag to pan, and use Fit scene to return to the full view. Select a character or a team card to highlight it.

Preview mode is labeled and contains sample actions. Live mode shows observed local sessions from the past 24 hours. Quiet, waiting and unconfirmed states remain distinct. The application observes agents; it does not control them.

Arrange your world

Choose Edit world beneath the scene. The editor works with every installed theme, including the bundled datacenter. No personal copy is required for layout changes.

  1. Select & move: click visible scenery or choose it in the placed-object list, then drag it to a new tile. The inspector also accepts exact column, row and height values. Mirror flips the artwork. Bridges use direction and span instead of height.
  2. Place scenery: choose an object from the palette and click a tile. Duplicate and Remove act on the selection.
  3. Paint terrain: choose a surface and drag across the map. One brush stroke is one undo step.
  4. Place a home / work destination: choose a character or activity destination, then click walkable ground. Homes appear as gold circles and work destinations as blue diamonds. Reposition these markers when relocating the stations they serve. Linked Borg alcoves and their home markers move together, including mirrored alcoves.
  5. Save layout: apply your arrangement and resume activity. Cancel discards the draft. Restore theme layout is an undoable draft action; save it to keep the reset.

Alt-drag pans while editing. Scroll zooms. Arrow keys move selected scenery; Delete removes it. Ctrl+Z and Ctrl+Y undo and redo. Animation pauses while the editor is open. Place scenery on the map so its footprint leaves residents room to walk; paths recalculate after editing.

Layouts are local to each theme and stored outside its downloaded files. Only your changed objects, terrain cells, homes and destinations are saved. Theme updates can supply new artwork, behavior and untouched scenery while retaining your changes. Saving detects an intervening layout or theme update; your draft stays open if a conflict occurs. An incompatible theme change shows a warning and keeps the saved layout on disk. The prior save is retained as a recovery copy.

Mooseville includes flowing water under its bridges and smoke from its chimneys. Chimney positions follow moved, mirrored and resized buildings. Reduce motion in Settings freezes ambient effects as well as character animation.

Theme library and personal copies

The GitHub catalog lists every available theme. Robot Datacenter is installed with the app. Mooseville preserves the original village and artwork; Orbital Station is a compact alternative. Smurfs adds six character types, mushroom homes, woodland scenery and individual character routines. Borg Cube adds eight distinct drones, a central Queen, workstations and 16 regeneration alcoves. Use Agent Watch 0.4.0 or later for its backward docking and animated lighting. Use Theme library to download and switch themes.

Choose Make a personal copy before replacing downloaded artwork or editing a full theme manifest. Use Edit world for layout changes. A copy has its own ID and stays on this computer. In Theme Studio you can change action mappings, assign characters, replace images, and edit the full theme manifest. The image replacement picker keeps the same file format; for a different format add the file in the theme folder and update the manifest.

Activity mappings and character assignments live outside the pack and survive updates. They belong to the theme where you set them. Personal copies have independent settings. If you edit a managed downloaded pack directly, updates to that pack are skipped until you preserve those edits in a personal copy.

Authoring a complete theme

A theme is a folder with theme.json and its referenced image assets. There is no executable theme code, remote script or CSS injection. All paths are relative and must remain inside the theme folder. PNG, WebP, JPEG, SVG and GIF images are accepted; use transparent PNG or SVG for characters and scenery. For animated characters, supply explicit frame lists; GIF assets are treated as images, not an animation timeline.

Assets and sprites

{
  "teal-idle": {
    "file": "assets/robots-a.png",
    "rect": [0, 0, 384, 341],
    "height": 64
  }
}

rect is the source rectangle in pixels: x, y, width, height. Omit it to use the whole image. Empty transparent margins are trimmed only while drawing; the source image is never altered. Set trim: false to retain the complete atlas cell for aligned animation frames. An optional anchor: [0.5, 1] gives the foot position as a fraction of the source rectangle. Every character needs an idle pose; walk and walk-back are optional. Any activity pose must exist on every character.

Characters and homes

{
  "id": "teal", "name": "Pip", "home": [4, 24],
  "poses": {
    "idle": "teal-idle",
    "walk": ["teal-walk-left", "teal-idle", "teal-walk-right"],
    "work": ["teal-work", "teal-idle"],
    "charge": "teal-idle"
  }
}

Home positions and activity targets use tile coordinates. Give characters distinct walkable home tiles. Put the charging station scenery just behind the home tile so the character can reach it. Scenery footprints block navigation; terrain with walkable: false is also blocked.

Reusable characters and individual routines

From Agent Watch 0.3.0, roleCharacters reserves those characters for their assigned roles during automatic selection. fallbackCharacter names the reusable character for additional agents after the other available characters have been assigned. Explicit user character assignments still take precedence. For example, Smurfs uses Papa for coordinators and the generic Smurf for additional agents.

Each character can optionally define bindings and idleActivities. Action resolution uses theme defaults, then character rules, role rules, and finally user overrides. A character idle list replaces the theme idle list for that character. Existing themes retain their shared routines.

Regeneration alcoves and object lighting

Borg Cube uses characters[].homeDock to link a character to a placed alcove ID and inactiveActivity: "regenerate" to send it home whenever it is not working. Explicit user state mappings can override this behavior. An alcove is reserved during the approach, turn, backward entry and regeneration. New work triggers an outward exit before routing to a workstation. Extra agents claim spare bays; if none is free they wait near home and retry. Removed or blocked bays are skipped.

objects.*.dock defines approach and entry tile offsets, turnSeconds, enterSeconds, exitSeconds, enterPose and restPose. Both poses must exist on every character. Keep the complete entry corridor walkable. Mirroring swaps the two tile axes for docking and its obstruction footprint. Moving a linked home moves its alcove; moving or mirroring an alcove updates its home.

objects.*.lights supports a six-digit color, speed, when: "always" or "occupied", circular nodes: [[x,y,radius]], optional bars with from, to and width, and an optional scan with the same fields. Coordinates are fractions of the rendered sprite; effects follow placement, mirroring and size. Occupied lighting activates after entry completes. The editor and Reduce animation and movement freeze light animation; reduced motion snaps docking to its destination.

The Borg Queen stays at her central nexus with command, scanning, communion and mechanical reassembly sequences. Preview activities cycles through them. See the Borg manifest and artwork for a complete example.

Custom activities

{
  "print-report": {
    "label": "Collecting a printed report",
    "pose": "work", "motion": "visit",
    "targets": [[12, 18], [16, 18]],
    "fps": 1.5, "duration": 14
  },
  "recharge": {
    "label": "Recharging at home",
    "pose": "charge", "motion": "home",
    "fps": 1, "duration": 24
  }
}

The four motion choices are stay, wander, visit and home. Visit activities require at least one target. Duration controls dwell time in the idle cycle and the interval between wandering routes. Working activities continue until the observed action changes. FPS controls the pose frame list; reduced motion uses still poses at the destination.

Add the activity ID to idleActivities to include it in downtime. Connect it to an action with "review": "print-report", or to an exact tool name with "tool:functions.exec": "print-report". Tool name matching is exact and case-sensitive. Tool-specific mappings apply only while working; waiting and completed states retain their own meanings.

Action names

started, build, read, research, review, delegate, message, coordinate, tool, wait, update, completed, interrupted, working, waiting, quiet, idle, unknown. Quiet or finished agents transition into the theme's idle cycle after the immediate action display.

Ambient effects

Add a data-only flow to a terrain definition: {"color":"#e4f8dd","speed":1,"direction":[0,1]}. Direction uses tile axes; moving texture and highlights are clipped to those cells. Add smoke to an object definition: {"anchor":[0.7,0.1],"color":"#e0e4d7","scale":1,"speed":1}. The chimney anchor is a fraction of the visible, trimmed sprite. Speed and smoke scale range from 0.1 to 5. Effects share the reduced-motion pause clock. Bridge definitions can provide deck: {"start":[0.132,0.216],"end":[0.89,0.829]} to align the artwork's open ends with its walkable span.

Publishing a theme

  1. Add a self-contained folder under themes/<id>/. The folder name must match the manifest ID.
  2. Run npm run themes:build to validate assets and regenerate SHA-256 package manifests and the catalog.
  3. Run npm test and npm run themes:check.
  4. Commit the theme and generated catalog to the repository's main branch. Installed applications can discover it at their next startup or catalog refresh.

Files are limited to 20 MiB each and packs to 180 MiB. Images may be shared between sprites using different rectangles. The complete Robot Datacenter and Orbital Station manifests are working examples.

Startup updates and stored data

Application updates come from public GitHub Releases in william-pyle/AgentWatch. The NSIS updater downloads the new installer, verifies its release checksum, and offers an explicit restart. Closing Agent Watch does not silently install a pending update. Other running applications and agent sessions are not restarted.

Theme updates use a separate GitHub catalog. Every file has a SHA-256 checksum. A content revision changes when any file changes, including changes that do not bump the theme's version. Downloads go into a new staging folder; only a complete verified pack is activated. The prior revision is retained. Offline or interrupted checks leave the last installed pack available. Theme updates can be disabled in Settings.

User data lives in %APPDATA%\Agent Watch\. Settings are in settings.json; per-theme layout patches are in layouts/<theme-id>.json with the prior save in <theme-id>.previous.json; managed theme revisions are under themes\versions\, and personal copies under themes\personal\. The base theme remains in the app's resources directory. Uninstalling keeps user data so reinstalling can restore your preferences.

No agent observations are uploaded. The collector reads local Codex and Claude logs and optional Alpha saved metadata in the chosen workspace. Only bounded observation metadata reaches the app display. Local transcript excerpts used by the original parser do not cross into the desktop feed or get written to reports.

Building and releasing

npm ci
node node_modules/electron/install.js
npm test
npm run themes:check
npm run test:desktop
npm run build

The x64 Windows installer is written to dist/. No installed Node runtime is needed by end users. The package includes only the Robot Datacenter base theme; optional theme packs remain in the repository.

For a release, update package.json and the lockfile, commit, then push a matching v0.2.0-style tag. The Windows GitHub Actions job validates, tests, builds and publishes the setup EXE, blockmap and latest.yml metadata. Do not remove update metadata from a release.

This release is unsigned because no Windows publisher certificate has been configured. GitHub release SHA-512 checksums and HTTPS remain in use. When adding signing, store credentials in GitHub Actions secrets, pass CSC_LINK/CSC_KEY_PASSWORD only to the build job, configure the publisher name, and enable win.verifyUpdateCodeSignature. Never place certificates or private keys in the repository.
